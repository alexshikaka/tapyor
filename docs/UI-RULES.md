# Правила интерфейса: чтобы новое сразу работало во всех оболочках

Короткая памятка для любой модели, которая добавляет или меняет что-то в окне Тапёра. Подробно об устройстве оболочек — `docs/SKINS.md`.

Главная мысль: **оболочка перекрашивает не «элементы», а переменные и общие классы**. Если новый элемент собран из них — он сам станет правильным в стандартной теме, в светлой, в «Монохроме» и во всех пиксельных оболочках. Если в нём зашит свой цвет, радиус или шрифт — он «выпадет».

## 1. Цвета — только переменные

| Что | Переменная |
|---|---|
| фон окна / приложения / панели / поверхности / наведение | `--bg00`, `--bg0`, `--bg1`, `--bg2`, `--bg3`, `--bg4` |
| границы (обычная / тише / ярче) | `--ln`, `--ln2`, `--ln3` |
| текст (от главного к слабому) | `--tx`, `--tx2`, `--tx3`, `--tx4`, `--tx5` |
| акцент, акцент при наведении, акцент `r,g,b`, подложка акцента | `--ac`, `--ac2`, `--acr` (`rgba(var(--acr), .3)`), `--acbg` |
| главная кнопка и текст на ней | `--pri`, `--prit` |

Нельзя: `#9B87FF`, `rgb(…)`, `white` в новом коде окна и в общих правилах `app.css`. **Проверка:** `node tools/ui-rules.mjs` (входит в `npm test`) — падает, если зашитых цветов стало больше. Исключения — палитры (сами оболочки `01-skins.js`, темы `06-themes.js`, панель OBS `13-widget.js`, правила `:root`, `theme-*`, `skin-*`): там цвета — это данные.

Цвет обложки (свечение, визуализатор) — допустим как значение, вычисленное из картинки, но рамки, текст и подложки вокруг — переменными.

## 2. Форма и размеры

- Скругления: `--r-panel` (карточки-панели, 20 px), `--r-card` (14), `--r-ctl` (кнопки, поля, 10). Пиксельные оболочки обнуляют все углы сами (`html.pixel-skin * { border-radius: 0 }`) — не бороться с этим `!important`.
- Отступы: `--sp-1…--sp-6` (4–24 px), поле вокруг рабочей области `--gutter`.
- Шрифт не задавать: наследуется от `body` (оболочки меняют его там). Моноширинный — только для цифр/кода, тем же способом, что в существующем коде.

## 3. Кирпичики — готовые классы

Новую кнопку, переключатель, карточку собирать из существующих классов, а не придумывать свои:

| Что | Класс |
|---|---|
| кнопка в ряду действий | `.pbtn` (+ `.y` главная, `.qadd` «в очередь», `.g` без фона) |
| обычная кнопка в настройках | `.btn` (+ `.ghost`) |
| переключатель | `.toggle` (+ `.on`, `aria-pressed`) |
| фишка-фильтр | `.chip` / `.wchip` (+ `.active`) |
| карточка / строка настроек | `.card`, `.srow` (`.sl`, `.st`, `.sd`) |
| поле ввода | `.field` |

Оболочки оформляют именно эти классы (пиксельная фаска, свечение CRT…). Нужен новый вид — сначала подумать, нельзя ли модификатором существующего класса; если нужен новый класс — **добавить его правила во все оболочки** (`app.css`, блоки `html.skin-dos/crt/retro`) в том же коммите.

Значки — встроенный `<svg>` с `currentColor` (цвет берётся от текста кнопки и меняется вместе с оболочкой).

## 4. Движение и энергия

- Бесконечные анимации — только декоративные и только с паузой в фоне: добавить селектор в правило `body.calm … { animation-play-state: paused }` в конце `app.css` или поставить элементу атрибут `data-anim`. Окно не в фокусе или свёрнуто — `body.calm`, кадры не рисуются (замер: бесконечная анимация = +18–25% ядра).
- Заставки — конечное число повторов, конец анимации = начальное состояние.
- Уважать `prefers-reduced-motion`.
- Таймеры `setInterval` — только пока виден их раздел (пример: полоса прокрутки настроек).

## 5. Проверка перед коммитом

1. `npm test` — синтаксис, ESLint, правила цветов, аудит оболочек (углы, шрифт, «плоские» панели, палитра).
2. `sh tests/ui/run.sh` — проверки интерфейса.
3. Глазами: скриншоты нового элемента в стандартной теме, «Монохроме», светлой и трёх оболочках (DOS, Неон-скан, Ретро-десктоп).

## 6. Новая оболочка (на будущее)

Добавил — `npm test` (аудит пройдёт все вкладки) и скриншоты. Если аудит нашёл «выпавший» элемент — чинится его классом (§3), а не правилом под конкретную оболочку.
