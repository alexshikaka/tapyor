# Обмен кода DonationAlerts (облачная функция)

Зачем: `client_secret` DonationAlerts нельзя класть в установщик — он достаётся из `app.asar`
за минуту, а установщики лежат в публичном `tapyor-releases`. Секрет живёт здесь, в переменных
окружения функции. Тапёр присылает только код авторизации и получает обратно токен.

Схема та же, что у `server/yc-report`.

## Развёртывание

1. Yandex Cloud → Cloud Functions → **Создать функцию**, имя `tapyor-da-token`.
2. Среда выполнения `nodejs22`, точка входа `index.handler`, таймаут 10 с, память 128 МБ.
3. Загрузить `index.js` и `package.json` из этой папки.
4. Переменные окружения:
   - `DA_CLIENT_ID` — ID приложения DonationAlerts;
   - `DA_CLIENT_SECRET` — ключ API того же приложения.
5. Включить **«Публичная функция»** — Тапёр ходит сюда без авторизации в облаке.
6. Скопировать «Ссылку для вызова».

## Подключение к Тапёру

Ссылка кладётся в `src/da.json` полем `proxyUrl`:

```json
{"clientId":"<ID приложения>","proxyUrl":"https://functions.yandexcloud.net/<id функции>"}
```

Секретного слова в файле быть не должно. На сборке файл создаёт `.github/workflows/build.yml`
из секретов `DA_CLIENT_ID` и `DA_PROXY_URL`.

Если `proxyUrl` нет, а `clientSecret` есть, Тапёр ходит к DonationAlerts напрямую — старый путь,
оставлен для совместимости со сборками до 0.27.4.

## Что функция проверяет

- только `POST`;
- `grant_type` — только `authorization_code` или `refresh_token`;
- `redirect_uri` — только `http://127.0.0.1:47219/da-callback`, чужой отклоняется.

Токены не пишутся в лог: в журнал идёт только тип запроса, код ответа и факт наличия токена.

## Что ещё стоит добавить

Функция публичная, как и `yc-report`: адрес достаётся из установщика, и кто угодно может
слать на неё запросы. Обмен чужого кода ничего не даёт (код выдаётся только через наш
`authorize`), но квоту потратить можно. Общий ключ в заголовке или лимит по частоте — в TODO.

## Общий ключ (SHARED_KEY)

Функция публичная: её адрес достаётся из установщика, и без ключа слать на неё запросы
может кто угодно. Поэтому Тапёр передаёт заголовок `x-tapyor-key`, а функция сверяет его
с переменной окружения `SHARED_KEY`.

Ключ **не секретный** — он лежит в установщике (`src/cloud-key.js`). Его задача — отсекать
случайные и автоматические запросы, а не защищать от целенаправленной атаки.

Как включить:

1. В переменные окружения функции добавить `SHARED_KEY` со значением из `src/cloud-key.js`
   (поле `CLOUD_KEY`).
2. Создать новую версию функции.

Пока `SHARED_KEY` не задан, функция пускает всех — так сборки, выпущенные до появления
ключа, продолжают работать. Включать стоит после того, как разойдётся версия с ключом.
