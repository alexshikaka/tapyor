# Облачная функция пульта с телефона — `tapyor-remote`

Тупой почтовый ящик между Тапёром и страницей пульта на телефоне. Функция видит только
зашифрованные куски (`base64url`) и не знает ключа сессии — содержимое (снимок пульта, лента,
команды) ей недоступно. Протокол и правила безопасности — `docs/REMOTE.md` в ядре.

Состав папки:

| Файл | Что делает |
|---|---|
| `index.js` | обработчик Yandex Cloud Functions: разбор запроса, выбор хранилища, логи (`op` и код) |
| `core.js` | вся логика без сети и YDB: `new`, `host`, `poll`, `cmd`, `end`, проверка формы, лимиты, CORS |
| `store-ydb.js` | хранилище в YDB (`remote_sessions`, `update` — в одной serializable-транзакции) |
| `schema.yql` | та же таблица для ручного создания (функция создаёт её сама) |
| `shared.js` | где взять `server/common/*.js`: рядом (собранная функция) или на уровень выше (репозиторий) |
| `dev-server.js` | локальный сервер для ручных проверок, хранилище в памяти, только `127.0.0.1` |

## Что нужно при выкладке

Среда — **Node.js 22**, точка входа **`index.handler`**, память и таймаут как у остальных функций
(128 МБ, 5 с). Переменные окружения (только имена):

| Переменная | Зачем |
|---|---|
| `PAGE_ORIGIN` | адрес сайта Тапёра для CORS страницы телефона, например `https://alexshikaka.github.io`. Не задана — `*` |
| `YDB_ENDPOINT` | адрес базы YDB (`grpcs://…`) |
| `YDB_DATABASE` | имя базы (`/ru-central1/…`) |
| `YDB_METADATA_CREDENTIALS` | `1` — вход сервисным аккаунтом функции (другой способ — ключ из окружения) |

Общий ключ `SHARED_KEY` этой функции **не нужен**: страница телефона его не знает, а доступ к
сессии защищён токеном `host` (в базе только его SHA-256) и лимитами частоты. Значений ключей в
архиве нет и быть не может — они живут только в переменных функции.

**Предел экземпляров.** В консоли функции задай предел копий (например, 2–3): лимиты частоты и
счётчик команд на сессию живут в памяти экземпляра, при малом числе копий они почти общие
(`docs/CLOUD-LIMITS.md`, `server/common/rate.js`).

## Как собрать и выложить

```bash
node tools/cloud-pack.mjs              # → dist/cloud/yc-remote/ и dist/cloud/yc-remote.zip
bash cloud-deploy.sh tapyor-remote yc-remote.zip
```

`cloud-pack.mjs` кладёт рядом с `index.js` ещё и `server/common/` — поэтому собранную папку можно
проверять как есть, а из репозитория функцию запускает только `dev-server.js` (он сам находит
`server/common`). Таблица `remote_sessions` создаётся при первом запросе; отдельно выполнять
`schema.yql` не обязательно.

### Проверка после выкладки

```bash
# новая сессия: ответ { sid, host, ttl }
curl -s -X POST "https://functions.yandexcloud.net/<id>?op=new" -H 'Content-Type: application/json' -d '{}'

# host: { sid, host, s, f } → { cmds: [], phoneAgo: null }
curl -s -X POST "https://functions.yandexcloud.net/<id>?op=host" -H 'Content-Type: application/json' \
  -d '{"sid":"…","host":"…","s":"AAAA","f":"BBBB"}'

# poll: { sid, sv, fv, es } → снимок и лента
curl -s "https://functions.yandexcloud.net/<id>?op=poll&sid=…&sv=0&fv=0&es=0"
```

В логах функции — только вид запроса и код ответа (`remote: host → 200`). Ни `sid`, ни `host`,
ни тела там не появляются.

## Локальная проверка без облака

```bash
node server/yc-remote/dev-server.js          # http://127.0.0.1:8879, хранилище в памяти
node server/yc-remote/dev-server.js 8890     # другой порт
```

Сервер переводит HTTP-запрос в `event` Yandex Cloud Functions и зовёт тот же `index.handler`.
Этого достаточно, чтобы сквозная проверка «страница телефона ↔ функция ↔ поддельный Тапёр»
работала без YDB и без сети. Порт по умолчанию 8879 не входит в занятый диапазон 8774–8805.

## Протокол коротко

| Запрос | Кто | Тело / параметры | Ответ |
|---|---|---|---|
| `POST ?op=new` | Тапёр | `{}` | `{ sid, host, ttl }` (`ttl` — миллисекунды, 43 200 000) |
| `POST ?op=host` | Тапёр | `{ sid, host, s?, f?, ev?, ack? }` | `{ cmds, phoneAgo }` |
| `GET ?op=poll&sid=…&sv=N&fv=N&es=N` | телефон | — | `{ sv, s?, fv, f?, ev, hostAgo }` |
| `POST ?op=cmd` | телефон | `{ sid, c }` | `{ ok: true }` |
| `POST ?op=end` | Тапёр | `{ sid, host }` | `{ ok: true }` |

Ошибки — `{ error, tapyor_error }`: `400 bad_request`, `403 forbidden` (чужой `host`),
`404 no-session` (истекла или «Отключить»; у неё нет `tapyor_error` — это обычный ответ),
`405 method`, `429 rate` (с `Retry-After`). CORS-заголовки отдаются только `poll`, `cmd` и
`OPTIONS` — остальные зовёт Node, браузеру они не нужны.

Ограничения: `sid` — 22 знака base64url (16 байт), `host` — 43 знака (32 байта); `s`/`f` ≤ 65 536
знаков, кусок события ≤ 16 384, `ev` ≤ 10 кусков за запрос, `c` ≤ 2 048; хранится 30 последних
событий и 50 команд; сессия живёт 12 ч от последнего `host`. Лимиты частоты: `new` — 10 за 10 мин
с адреса, `poll`+`cmd` и `host` — по ≈ 3000 за 10 мин с адреса, `cmd` — не чаще 20 за 10 с на сессию.
