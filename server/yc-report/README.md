# Посредник отчётов об ошибках (Yandex Cloud Functions → GitHub Issues)

Тапёр отправляет сюда короткий анонимный отчёт (POST JSON: fp, service, stage, code, msg, details, app, recipes, os, iid).
Функция ищет задачу с меткой `fp-<отпечаток>`: есть — обновляет счётчик пользователей/версий в описании; нет — создаёт новую
(не больше 30 в сутки). Закрытая задача с меткой `fixed-in-X.Y.Z` не переоткрывается отчётами со старых версий.
Личное (пути, почта, ключи, длинные токены) вырезается и в программе, и здесь.

Архив **не хранится в репозитории** и не собирается руками: функция использует общий код
`server/common/*.js`, поэтому архив собирает упаковщик из текущего кода.

Развёртывание:

1. Из корня репозитория: `node tools/cloud-pack.mjs` → `dist/cloud/yc-report/` и `dist/cloud/yc-report.zip`.
   В архиве `index.js`, `package.json` и папка `common/`.
2. Cloud Shell: `bash cloud-deploy.sh tapyor-report dist/cloud/yc-report.zip` — создаст новую версию
   с теми же настройками и переменными, что у текущей (`docs/CLOUD-DEPLOY.md`, раздел 3).
3. Если функция создаётся впервые: Cloud Functions → новая функция → Node.js 18+ → ZIP
   `dist/cloud/yc-report.zip` → точка входа `index.handler`, таймаут 10 с, память 128 МБ → переменные
   `GITHUB_TOKEN` (fine-grained, только Issues: Read and write на этот репозиторий) и
   `GITHUB_REPO=alexshikaka/tapyor-player` → сделать функцию публичной → адрес вида
   `https://functions.yandexcloud.net/<id>` вписать в Тапёр (REPORT_URL в main.js).

## Общий ключ (SHARED_KEY)

Функция публичная: её адрес достаётся из установщика, и без ключа слать на неё запросы
может кто угодно. Поэтому Тапёр передаёт заголовок `x-tapyor-key`, а функция сверяет его
с переменной окружения `SHARED_KEY`.

Ключ **не секретный** — он лежит в установщике (`src/cloud-key.js`). Его задача — отсекать
случайные и автоматические запросы, а не защищать от целенаправленной атаки.

Как включить:

1. В переменные окружения функции добавить `SHARED_KEY` со значением из `src/cloud-key.js`
   (поле `CLOUD_KEY`).
2. Создать новую версию функции.

Пока `SHARED_KEY` не задан, функция пускает всех — так сборки, выпущенные до появления
ключа, продолжают работать. Включать стоит после того, как разойдётся версия с ключом.
