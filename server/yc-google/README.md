# Обмен кода Google (облачная функция)

Зачем: `client_secret` не должен лежать в установщике. Для десктопных клиентов Google сам
не считает его конфиденциальным, но к версии с открытым кодом секретов в пакете быть не должно.
Схема та же, что у `server/yc-da` и `server/yc-report`.

## Развёртывание

1. Yandex Cloud → Cloud Functions → **Создать функцию**, имя `tapyor-google-token`.
2. Среда `nodejs22`, точка входа `index.handler`, таймаут 10 с, память 128 МБ.
3. В редакторе заменить содержимое `index.js` на файл из этой папки.
4. Переменные окружения:
   - `GOOGLE_CLIENT_ID` — Client ID из Google Cloud Console (оканчивается на `.apps.googleusercontent.com`);
   - `GOOGLE_CLIENT_SECRET` — секрет того же клиента.
5. Сохранить изменения, затем в «Обзор» включить **«Публичная функция»**.
6. Скопировать «Ссылку для вызова».

## Подключение к Тапёру

Ссылка кладётся в `src/google-oauth.json` полем `proxyUrl`:

```json
{"clientId":"...apps.googleusercontent.com","proxyUrl":"https://functions.yandexcloud.net/<id>"}
```

Секрета в файле быть не должно. На сборке файл создаёт `.github/workflows/build.yml`
из секретов `GOOGLE_CLIENT_ID` и `GOOGLE_PROXY_URL` (старый `GOOGLE_OAUTH_JSON` больше не нужен).

## Особенность Google: порт возврата случайный

У DonationAlerts адрес возврата постоянный, а Тапёр для Google поднимает сервер на свободном
порту и отдаёт `http://127.0.0.1:<порт>/cb`. Поэтому функция проверяет не точное значение,
а форму: только `127.0.0.1` и только путь `/cb`.

PKCE при этом работает как и раньше: `code_verifier` просто передаётся через функцию,
проверяет его сам Google.

## Проверка

Вкладка «Тестирование», входные данные:

```
{"httpMethod":"GET"}
```

Ожидается `statusCode 405` и `{"error":"only POST"}`.

```
{"httpMethod":"POST","body":"{\"grant_type\":\"refresh_token\",\"refresh_token\":\"zzz\"}"}
```

Ожидается ошибка от самого Google (`invalid_grant` или похожая), но **не** `not-configured` —
последнее означает, что переменные окружения не заданы.

## Общий ключ (SHARED_KEY)

Функция публичная: её адрес достаётся из установщика, и без ключа слать на неё запросы
может кто угодно. Поэтому Тапёр передаёт заголовок `x-tapyor-key`, а функция сверяет его
с переменной окружения `SHARED_KEY`.

Ключ **не секретный** — он лежит в установщике (`src/cloud-key.js`). Его задача — отсекать
случайные и автоматические запросы, а не защищать от целенаправленной атаки.

Как включить:

1. В переменные окружения функции добавить `SHARED_KEY` со значением из `src/cloud-key.js`
   (поле `CLOUD_KEY`).
2. Создать новую версию функции.

Пока `SHARED_KEY` не задан, функция пускает всех — так сборки, выпущенные до появления
ключа, продолжают работать. Включать стоит после того, как разойдётся версия с ключом.
